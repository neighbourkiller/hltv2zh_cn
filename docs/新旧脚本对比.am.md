当前项目更适合持续维护；旧脚本适合作为补齐遗漏的词条与场景库。新版已覆盖大量核心页面，不能再用“新版只覆盖基础功能”概括。两者均有覆盖盲区，尚无同条件性能对照数据。

## A 总体取舍

| 维度 | 当前项目 0.1.11 | NEXT 1.7.0 | 判断 |
|---|---|---|---|
| 翻译策略 | 页面模块、局部选择器、完整词条和句式 | 上下文规则加全局词典与正则管道 | 新版更可控；旧版容易覆盖零散文案 |
| 核心页面 | 比赛、赛事、选手、统计、战队、两类排名及明细 | 多页面规则集中在单文件 | 覆盖各有差异，不能用词条数量判胜负 |
| 动态更新 | 监听 Text、增量子树及四类属性 | 新增节点、title、class；WeakSet 跳过已处理节点 | 新版更适合同一文本节点反复更新 |
| 原站结构 | 保存原 Text，主要改文字和展示属性 | 部分分支覆盖父容器或插入节点 | 新版更利于保留图标、链接和事件 |
| 配置 | 总开关、页面模块、地图偏好、诊断 | 无对应 GM 菜单与持久配置 | 新版用户控制更完整 |
| 工程维护 | TypeScript、分层目录、夹具与回归 | 单个 JS 文件，直接修改安装 | 新版长期维护好；旧版入门修改简单 |
| 发布安装 | 生成单文件，暂需手动覆盖升级 | 元数据已有 Greasy Fork 更新地址 | 旧版分发机制更完整；地址可用性未核验 |

## B 新版的主要优势及证据

**动态文本不会因为“翻译过”就永久跳过。** 引擎用 WeakMap 保存源文和译文。网站改写同一个 Text 后，可将新内容识别为新的源文。旧版 WeakSet 只记录节点身份，且未监听 characterData；600ms 全页遍历也不会自动清除该标记。

**更可靠地保留原站交互。** 新版翻译 Text.data，避免重建父容器。旧版在阵容时间线、导航、提示等分支使用 innerHTML。执行这些分支时，原子节点会被替换；依附于子节点的监听器或引用有失效风险。这里是源码风险，不是本轮观察到的线上故障。

**更重视数据语义。** 新版对无显式 value 的 option 固定原值，避免翻译改变筛选参数。日期主要翻译已显示文案，不重新计算时区。旧版 eventdate 分支用本地 Date 重算并覆盖整个单元格；当站点时区不同，存在显示偏差风险。

**保护方式更易扩展。** 新版按正文、实体容器和链接语义保护。旧版也有大量排除选择器，不能说它完全不保护实体；但仍依赖有限名字名单和全局替换。新名字和普通英文词重合时，更难兜住。

**术语与数量更准确。** 旧版将部分 Average damage per round 译为“场均伤害”，分母不够准确；新版相关词条使用“每回合平均伤害”。旧版 ALL(数字) 分支直接返回“全部”，会丢数量。新版对应筛选保留数字节点。

## C 旧版仍值得保留的优势

**零散场景积累多。** 旧版包含论坛分类及说明、比赛表格 tooltip、手枪局指标、推荐比赛空状态和转会短句等规则。新版部分相关区域尚无专属适配，这些规则值得逐项迁移核验。

**文案变化的容忍度较大。** 全局词边界替换可能翻译没有专用适配器的页面。代价是上下文不足时会误翻，或者生成中英拼接句。新版完整匹配遇到未知句式会保留英文，覆盖增长需要更多人工采样。

**修改和分发成本低。** 旧版没有构建依赖，修改 JS 即可安装。它已有更新元数据，且使用 grant none。新版安装产物仍是单文件，但开发者需要 Node、构建工具和测试环境；三个 GM 权限用于配置与菜单，本身不代表不安全。

**对部分 class 变化有补偿。** 旧版监听 class，并专门重新处理 round-header。新版目前不监听 class，这个具体场景是旧版机制上的优势。但普通隐藏标签页的显示切换，若内容已在初始扫描中翻译，并不一定需要再次处理。

## D 当前项目仍有的短板

| 短板 | 源码依据与影响 | 建议 |
|---|---|---|
| class 与部分语义属性变化未触发重译 | runtime 只监听 title、placeholder、aria-label、alt；仅 class 改变规则归属时可能漏译或保留旧译文 | 用真实样本添加局部监听，避免监听全部 class 引起噪声 |
| 路由只在启动时识别一次 | start 中固定 page；若未来站点使用无刷新跨路由，模块不会自动切换 | 确认实际需要后加入导航检测与重建 |
| 地图默认全站匹配 | maps.text 使用 *；绕过了非目标区域的选择器快速过滤 | 对地图做廉价完整词条预判，补实体同名反例 |
| 地图语义仍有歧义 | 未被保护的独立 Train 等词，也可能不是地图 | 精确词条不等于语义识别，继续细化保护 |
| 规则搜索仍为线性 | resolve 遍历当前激活规则，逐一 matches | 按属性、区域或规则组索引；先测量再优化 |
| 6ms 预算不是硬上限 | 时间在一次节点处理后检查，单次处理可能超时 | 记录批次耗时分布，避免承诺绝不卡顿 |
| 限流后没有自动重试 | 超频字段暂停 10 秒，但无到期任务 | 若最后一次更新被跳过，需后续变更或刷新才能重译 |
| 精确选择器依赖结构 | 直属父元素、类名、部分列位置改变会漏译 | 多布局、多实体及空状态夹具补齐 |
| 菜单修改会刷新页面 | main 传入 location.reload | 有未提交输入时需留意；后续可考虑原位更新 |
| 覆盖和发布仍未收尾 | 其他 Stats 控件、VRS 模拟器、独立转会和 Fantasy 未完整覆盖 | 按使用频率补适配，再完善发布更新渠道 |

这些是当前实现的边界或条件性风险，不表示每项都已在 HLTV 实页复现。地图规则也仍受正文和实体保护，并非任意子串替换。

## E 性能与测试：能证明什么

新版采用任务去重、可续跑遍历及分片调度。每批默认约 6ms 或 300 次迭代，另有 100ms 调度兜底。初始扫描之后主要处理变化区域；菜单更新或 BFCache 返回等操作仍可能主动扫描全页。

旧版在 observer 回调中直接遍历新增区域，并安排 600ms 防抖后的全页扫描。它不是“每 600ms 固定扫描”。WeakSet 降低已处理 Text 的替换成本，但 TreeWalker 仍要走过节点；持续变化也可能推迟防抖扫描。

因此，新版在调度和避免重复遍历上更有优势，但不能声称“快多少倍”。新版全局地图规则、保护选择器和规则线性搜索也有成本。当前产物约 116 KB，旧版约 92 KB；文件大小同样不能代替运行性能指标。

仓库 0.1.11 验收记录载明：58 项单元/DOM 测试和 64 项双视口 Chromium 回归通过。记录还包含部分排名页、战队七标签页和 V社五分项的临时实页运行。持久安装升级、完整浏览器矩阵和全站验收仍未完成。

本轮审查了源码和测试内容，没有重新执行测试、安装脚本或做新旧同条件实页性能测试。上述通过数量引用仓库验收记录，不是本轮重跑结果。

## F 后续迭代优先级

1. 用旧版规则建立迁移清单，逐项标记已覆盖、待迁移和有意舍弃。
2. 优先补常用比赛 tooltip、统计控件及转会界面；每项附 DOM 与实体保护用例。
3. 补 class 切换、限流到期和地图同名实体的针对性回归。
4. 用同一 DOM 和变更序列对比两版耗时、长任务、写入数及错误翻译。
5. 完成真实 Tampermonkey 升级、设置持久化与实际浏览器验收。
6. 建立发布地址和自动更新，再扩展低频页面。

保留当前引擎作为主线，迁移旧版中有价值的场景。直接合并两套翻译管道，会重新引入覆盖顺序、重复写入和原文恢复冲突。
