# 性能基线与 0.1.12 首轮结果

阶段 C 的最终 0.1.13 配对测量另见 [阶段 C 性能结果](阶段C性能结果.md)，本文件保留首轮历史数据。

日期：2026-10-09。结果来自本机隔离 Chromium 与本地合成夹具，不代表 HLTV 全站速度或实际浏览器管理器沙箱性能。

## 测量方法

- 脚本：`scripts/benchmark.mjs`。所有请求拦截到本地 `hltv.test`，其他请求中止。
- 版本：历史 NEXT 1.7.0、修改前冻结的 0.1.11、本轮 0.1.12。每版使用独立页面，不同时运行两套翻译脚本。
- 环境：Windows、Node 24.21.0、Chromium 156.0.8078.4、AMD Ryzen 7 7840H、1440×900。
- 每组预热 1 次，记录 5 次。旧版和冻结基线轮换执行顺序；新版在构建验证后单独执行，相同机器与配置，但不是同时段配对测量。
- 0.1.11 与旧版测量在源码修改前启动；部分时段存在开发工具活动。结果用于建立数量级基线，微小差异不能解释为优化收益。
- 初始、插入、长表格的观察窗口为 2.2 秒；原 Text 每 40ms 更新 30 次，窗口仍为 2.2 秒；争夺场景每 25ms 更新 30 次，观察 11.5 秒，覆盖 10 秒冷却。非初始场景先等待 1.5 秒稳定。
- 记录 Text 变化、TreeWalker 返回节点、observer 回调、长任务及最终翻译/实体状态。`cpuMs` 只包含 observer 回调，不包含新版 rAF 处理，**不能用来比较总 CPU**。
- TreeWalker 计数不含直接入队的 Text、遍历根节点和其他选择器查询，不等于引擎总处理数。写入次数在高频场景包含 30 次夹具模拟的站点写入。
- 长任务包含测量与夹具开销；不能将全部长任务都归因于翻译脚本。只有 5 次有效样本，尾部采用最大值而非声称可靠 p95。

## 结果

前 3 项时间为测量开始至最后一次 Text 变化的中位数 / 最大值；确认全部目标已翻译后，才能把它视为该夹具的文本完成延时。

| 场景 | NEXT 1.7.0 | 0.1.11 | 0.1.12 | 完整性 |
|---|---:|---:|---:|---|
| 初始 1,500 条相对时间 + 普通英文 | 155.1 / 160.4ms | 341.8 / 348.2ms | 342.5 / 368.3ms | 三版每次均翻译 1,500 条 |
| 动态插入 1,500 条 + 普通英文 | 117.8 / 127.3ms | 478.6 / 490.3ms | 483.6 / 487.5ms | 三版每次均翻译 1,500 条 |
| 1,500 行三列表格 | 156.6 / 167.7ms | 594.6 / 606.7ms | 606.7 / 611.8ms | 三版每次均翻译 1,500 个地图单元格 |
| 插入场景 TreeWalker 返回节点 | 9,009 | 3,000 | 3,000 | 只代表 walker 内节点，不是所有处理工作 |
| 静置 2.2 秒新增 Text 写入 | 0 | 0 | 0 | 三版均无持续写入 |
| 争夺停止后的最终标题正确次数 | 0/5 | 0/5 | 5/5 | 新版约在测量开始后 10.54 秒恢复 |
| 独立 Ancient 队名链接保持次数 | 0/5（每场景） | 5/5（每场景） | 5/5（每场景） | 旧版在该反例中误译为地图 |
| 所有正式样本中最大长任务 | 129ms | 未记录到 ≥50ms 任务 | 未记录到 ≥50ms 任务 | 仅限本地测量窗口 |

每 40ms 更新的短窗口里，两版新脚本均触发了每秒 20 次的限流，在 2.2 秒窗口末仍为英文；旧版则没有重新翻译这些已处理的 Text。该场景的 `finalCorrect=false` 不表示 0.1.12 冷却恢复失败，完整冷却由 11.5 秒场景单独验证。三版均保持新闻正文反例不变。

## 结论与实施取舍

1. 新版分片策略牺牲部分“整批文字全部完成”的延时，避免在这些样本中出现旧版初始/长表格的长任务。不能据此声称新版所有指标更快。
2. 0.1.12 相比冻结基线，前三项中位数变化约为 +0.2%、+1.0%、+2.0%，未达到方案中 20% 的调查触发线；没有可证明的端到端提速。
3. 地图候选判断减少不必要的通用规则解析和实体保护查询；目前保留这项小范围改动，不进一步建立复杂规则索引。
4. 核心收益是故障恢复：在同一最终英文写入后，0.1.12 会到期重查并翻译；0.1.11 和旧版在观察窗口内不会恢复。
5. 全部测试样本的地图与相对时间数量保持；旧版更快完成但误译了同名队伍，速度与正确性必须分开评价。
